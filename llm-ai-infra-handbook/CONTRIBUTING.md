# Contributing

感谢为 LLM & AI Infra Handbook 补充知识、实验或工程经验。提交应优先追求可验证性，而不是追求术语数量。

## 内容贡献

1. 先阅读 `backend/kb/README.md`，确认卡片属于哪个模块；不要以产品名或厂商名新建顶层分类。
2. 一张卡片只回答一个稳定问题。框架操作手册放进 `labs/`，速查信息放进 `reference/`。
3. 结论必须说明适用条件；性能结论应给出输入规模、精度、硬件、负载与测量口径。
4. `source` 优先使用论文、标准、官方文档或源码。二手文章可以辅助理解，但不应成为关键结论的唯一证据。
5. `questions` 写成用户或面试官真实会问的自然语言，不要只是重复标题。
6. 保留现有卡片 `id`。移动目录或修改标题时不要改 ID，以免本地学习记录失联。

## 卡片结构

推荐使用：一句话结论、原理与系统位置、工程权衡、具体例子、观测与排障、面试追问。公式、代码或数据只在能帮助验证结论时加入。

## 提交前检查

```bash
python tools/validate_frontmatter.py
python -m unittest discover -s backend/tests -p 'test_*.py' -v
```

新增或改变检索语料时，还应使用固定问法集报告变更前后的 Top-1 / Top-5 命中率；这项评测基础设施在 v0.4/C1 中继续建设。
