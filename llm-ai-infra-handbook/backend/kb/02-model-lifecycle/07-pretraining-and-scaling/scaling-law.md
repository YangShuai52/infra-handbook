## 一句话结论

Scaling Law 是"**用小规模实验预测大规模结果**"的经验幂律，它让"花多少钱能换多少能力"变成可计算的工程问题。

三个版本的关系：

```
Kaplan (2020):     L = 幂律(N, D, C)，参数量是最有效的投入方向
Chinchilla (2022): 修正指数，参数与数据应等比例放大 → 每参数 20 token
实践 (2023~):      普遍"过训练"，每参数 200~2000 token，用训练算力换推理成本
推理时代 (2024~):  新增一个维度 —— test-time compute（推理时算力也能换能力）
```

## 原理推导

### 1. Kaplan 版本

核心发现：测试损失与三个量各自呈幂律关系（在其他量不受限时）：

```
L(N) = (N_c / N)^α_N        α_N ≈ 0.076
L(D) = (D_c / D)^α_D        α_D ≈ 0.095
L(C) = (C_c / C)^α_C        α_C ≈ 0.050
```

关键结论：

1. **性能主要由规模决定，与架构/超参弱相关**（宽度、深度、头数在很宽的范围内对 loss 影响很小，只要总参数量相同）
2. **`α_D > α_N`**，意味着在"参数和数据都不受限"时，单纯增大数据收益更大；但 Kaplan 的实际建议是**优先增大参数**，因为那时大家默认用固定数据量训练
3. 过拟合的惩罚项：当 D 相对 N 太小时，`L = (N_c/N)^α_N + (D_c/D)^α_D` 的第二项会主导

### 2. Chinchilla 版本（Hoffmann et al. 2022）

方法论改进：训练了 400 多个模型，覆盖不同的 (N, D) 组合，用**三维拟合**而不是分离拟合：

```
L(N, D) = E + A / N^α + B / D^β
```

拟合结果：

```
E = 1.69    (不可约损失，即语言本身的熵)
A = 406.4,  α = 0.34
B = 410.7,  β = 0.28
```

**最优分配的推导**：在算力约束 `C = 6ND`（训练 FLOPs）下最小化 L。用拉格朗日乘子法：

```
min L(N,D)  s.t.  6ND = C
∂L/∂N = -αA/N^(α+1),  ∂L/∂D = -βB/D^(β+1)
约束: D = C/(6N)

代入，对 N 求导 = 0:
αA/N^(α+1) = βB · (6N/C)^(β+1) · 1/N   （详细展开略）
→ N_opt ∝ C^(β/(α+β)),  D_opt ∝ C^(α/(α+β))
```

代入 α=0.34, β=0.28：

```
N_opt ∝ C^0.452 ≈ C^0.5
D_opt ∝ C^0.548 ≈ C^0.5
```

即**参数量和数据量应等比例放大**（都在 √C 量级）。数值结论：

```
D / N ≈ 20  tokens per parameter
```

**Chinchilla 本尊**：70B 模型用 1.4T tokens 训练，击败了 280B 的 Gopher（只用 300B tokens）——同样算力下，小模型 + 多数据完胜。

### 3. 与 Kaplan 的换算关系

Kaplan 给出的是 `C ≈ 6ND`，并建议 `D ∝ N^0.74`（即数据增长慢于参数）。Chinchilla 的 `D ∝ N^1.0`。差异来源：

- Kaplan 用的学习率调度没有完全收敛到最优（对大模型影响更大，导致高估参数的作用）
- Kaplan 只训了少量大模型点，外推误差大

统一的理解：**两者都是同一幂律曲面在不同区域的切片**，Chinchilla 的拟合更可靠。

### 4. 为什么实践上要"过训练"

如果 Chinchilla 最优是 20 tokens/param，为什么：

```
LLaMA-1 7B:   1.0 T tokens  → 约 143 tokens/param（7 倍过训练）
LLaMA-2 7B:   2.0 T tokens  → 约 286 tokens/param（14 倍）
LLaMA-3 8B:  15.0 T tokens  → 约 1875 tokens/param（94 倍）
Qwen2.5 系列: 18 T tokens
```

**经济学的理由**：

```
训练成本: 一次性，6ND FLOPs
推理成本: 每次调用 2N FLOPs × 服务次数

若模型服务 1e12 次请求/年，推理总 FLOPs = 2 × 7e9 × 1e12 = 1.4e22
而训练 7B × 1T tokens = 4.2e22 FLOPs
→ 一年的推理成本是训练成本的 1/3，且模型会服务多年
```

结论：**把模型做小、把数据做多，总拥有成本更低**。所以工业界系统性地偏离 Chinchilla 最优点。

定量规律（"过训练的边际收益"）：数据从 20 提到 200 tokens/param 时，loss 继续显著下降；超过约 500 tokens/param 后收益很小。所以过训练也有上限，不是越多越好。

### 5. 推理时扩展（Test-time Scaling / Inference Scaling）

2024 之后的新维度：能力不再只是 `f(N, D)`，而是 `f(N, D, C_inference)`。

两条路径：

1. **并行采样**：生成 k 个候选，用 verifier/投票选出最好的（Best-of-N、self-consistency）
2. **串行思考**：让模型生成长链推理（CoT），再给答案——本质是用推理算力换取"更多的中间计算步"

关键发现：

```
在可验证任务（数学、代码）上，推理时算力与训练算力可以互相替代
且在固定总算力预算下，存在一个最优分配
```

这催生了推理模型（o1 / R1 类）的训练范式：用 RL 让模型学会**把算力分配到思考过程**上（见 GRPO 与 RLVR 一篇）。

幂律形式上，可以理解为：

```
错误率 ∝ (N^α · D^β · C_test^γ)^(-1)
```

γ 的具体值依赖任务（可验证任务的 γ 明显大于开放式生成任务）。

### 6. Scaling Law 的失效与边界

1. **涌现能力（Emergent Abilities）是否真实**：很多"涌现"被证明是**度量 artifacts**——用不连续的指标（如精确匹配）看，能力曲线会有突变；用连续指标（如 log loss、Brier score）看，是平滑的对数线性改进。所以"规模到了 X 就突然会了"多数是评测假象。
2. **数据墙**：高质量公开文本总量约 10^13 tokens 量级（含代码、多语言、多模态），按 Chinchilla 折算，能喂饱的最优模型在万亿参数级别；再往上要靠合成数据或多模态数据。
3. **推理成本墙**：模型大到一定程度，即使训练得起也部署不起。

## 具体例子

**例 1：给定算力预算反推最优配置**

预算：`1e24` FLOPs（约等于 1000 张 A100 跑 40 天的量级）。

```
C = 6ND = 1e24，且 D = 20N
→ 6 × N × 20N = 1e24
→ 120 N² = 1e24
→ N² = 8.33e21
→ N = 9.13e10 = 91.3 B 参数
→ D = 20 × 9.13e10 = 1.83e12 = 1.83 T tokens
```

检验：

```
6 × 9.13e10 × 1.83e12 = 1.00e24 ✓
```

**例 2：Chinchilla vs Gopher 的实际对比**

| 模型 | 参数 | 训练 token | 训练 FLOPs | 结果 |
|---|---|---|---|---|
| Gopher | 280B | 300B | 5.0e23 | 基准 |
| Chinchilla | 70B | 1.4T | 5.9e23 | **全面超越 Gopher** |

同样算力，参数量减到 1/4、数据增到 4.7 倍，效果更好。注意 Chinchilla 的 FLOPs 略高（5.9 vs 5.0），但就算折算到相同算力，结论不变。

**例 3：过训练的经济账**

假设：7B 模型服务 3 年，每天 1 亿次请求，每次生成 500 token。

```
训练 (1T tokens):   6 × 7e9 × 1e12 = 4.2e22 FLOPs
推理 (3 年):        2 × 7e9 × 1e8 × 500 × 365 × 3 = 7.67e23 FLOPs

推理 / 训练 = 18.3×
```

所以：让训练成本增加 2 倍（多训数据），换取推理时模型从 13B 降到 7B（推理成本降 46%），总账是划算的。这就是过训练的商业逻辑。

**例 4：用幂律预测**

已知 1B 模型在 20B token 上的 loss = 2.5，用 Chinchilla 公式预测 10B 模型在 200B token 上的 loss（参数和数据都 ×10，保持 20 tokens/param）：

```
L(1e9, 2e10)  = E + A/N^α + B/D^β = 1.69 + 406.4/(1e9)^0.34 + 410.7/(2e10)^0.28
(1e9)^0.34 = 10^(9×0.34) = 10^3.06 = 1148  → 406.4/1148 = 0.354
(2e10)^0.28 = 10^(10.301×0.28) = 10^2.884 = 766  → 410.7/766 = 0.536
L = 1.69 + 0.354 + 0.536 = 2.58（与假设的 2.5 接近，公式自洽）

L(1e10, 2e11):
(1e10)^0.34 = 10^3.4 = 2512 → 406.4/2512 = 0.162
(2e11)^0.28 = 10^(11.301×0.28) = 10^3.164 = 1459 → 410.7/1459 = 0.282
L = 1.69 + 0.162 + 0.282 = 2.13
```

即 10 倍规模带来 loss 从 2.58 降到 2.13，**可约损失（L - E）从 0.89 降到 0.44，减半**。这就是"规模每增 10 倍，可约损失按幂律下降"的直观含义。

## 代码速记

```python
import math

# ---------- Chinchilla 拟合参数 ----------
E, A, B, ALPHA, BETA = 1.69, 406.4, 410.7, 0.34, 0.28

def chinchilla_loss(N, D):
    """N: 参数量, D: token 数"""
    return E + A / N**ALPHA + B / D**BETA

def optimal_alloc(C, tokens_per_param=20):
    """给定算力预算 C (FLOPs)，返回最优 (N, D)"""
    # C = 6ND, D = k·N  →  6kN² = C
    k = tokens_per_param
    N = math.sqrt(C / (6 * k))
    D = k * N
    return N, D

def flops(N, D):
    return 6 * N * D

def training_time(N, D, n_gpus=1024, peak=312e12, mfu=0.4):
    """A100 bf16 峰值 312 TFLOPS"""
    total = flops(N, D)
    eff = n_gpus * peak * mfu
    return total / eff          # 秒

# 1e24 FLOPs 预算
N, D = optimal_alloc(1e24)
print(f"N={N/1e9:.1f} B, D={D/1e12:.2f} T tokens")
# N=91.3 B, D=1.83 T
print(f"1024卡耗时: {training_time(N, D)/86400:.1f} 天")

# ---------- 过训练的经济账 ----------
def tco(n_params, train_tokens, daily_requests, gen_tokens, years=3):
    train = 6 * n_params * train_tokens
    infer = 2 * n_params * daily_requests * gen_tokens * 365 * years
    return {"train": train, "infer": infer, "ratio": infer / train}

print(tco(7e9, 1e12, 1e8, 500))
# ratio ≈ 18.3

# ---------- 推理时扩展：Best-of-N 的成功率 ----------
def best_of_n(p_single, n):
    """至少一次成功的概率（假设独立采样且有完美 verifier）"""
    return 1 - (1 - p_single) ** n

for n in [1, 4, 16, 64]:
    print(f"BoN={n}: {best_of_n(0.15, n):.3f}")
```

## 面试追问

**Q：Scaling Law 是物理定律吗？**
A：不是，是**经验拟合**。它描述的是"在当前的架构、数据分布、优化方法下，loss 与规模的统计关系"。改变架构（如从 Transformer 换成 Mamba）、改变数据质量（如用合成教科书数据）、改变优化器，幂律的系数和指数都会变。它的价值在于**在同一技术范式内做外推预测**，不能跨范式比较。

**Q：Chinchilla 说每参数 20 token，为什么大家不遵守？**
A：因为 Chinchilla 优化的是"给定训练算力下的最优 loss"，而工业界优化的是"给定总成本下的最优服务能力"。训练是一次性成本，推理是持续成本，模型越小服务成本越低。所以宁可多花训练算力把小模型训透（过训练 10~100 倍）。例外情况是：如果你只训一个模型用于离线评估、不做大规模服务，那确实应该遵守 Chinchilla。

**Q：涌现能力是真的吗？**
A：大部分是评测假象。斯坦福的 "Are Emergent Abilities of Large Language Models a Mirage?" 指出：当使用**不连续或非线性**的指标（精确匹配、多选正确率）时，平滑改进的能力曲线会在某个点"看起来"突然跃升；改用连续指标（如 token 级 log probability、Brier score）后，曲线是平滑的。所以严格意义上的"量变引起质变"在 LLM 上证据不足。但有一个真实现象值得承认：**某些复合任务（多步推理）需要多个子能力同时达到一定水平才能做对，指标上确实会呈现阈值效应**。

**Q：数据不够了怎么办？**
A：这是当前的核心瓶颈（"数据墙"）。四条路：(1) **多模态数据**（图像、视频、音频蕴含的信息量远大于文本）；(2) **合成数据**（但要警惕模型坍缩）；(3) **更高效的利用**（去重、课程学习、多次 epoch 配合正则）；(4) **推理时扩展**（用推理算力替代部分训练算力）。实践中四条都在用。

**Q：Scaling Law 对小模型微调还适用吗？**
A：形式不同。预训练的 Scaling Law 描述的是"从零学习的 loss 曲面"；微调场景下的规律是：能力随基础模型规模平滑提升，但**存在一个"任务阈值"**——某些能力（如复杂指令跟随、多步推理）在小模型上无论多少微调数据都学不会，必须基础模型先具备。另外微调数据量的边际收益递减极快，通常几百到几万条高质量样本就饱和了。

**Q：如何验证一个 Scaling Law 拟合是否可信？**
A：三个检查。(1) **跨至少两个数量级的规模范围**拟合（一个数量级内的幂律很容易被其他函数拟合）；(2) **预测留出点**：用小规模拟合，预测大规模，看误差（Chinchilla 论文的关键方法）；(3) **检查残差结构**：如果残差随规模系统性变化，说明函数形式不对。另外要警惕用最终 loss 而非 held-out loss 拟合。
