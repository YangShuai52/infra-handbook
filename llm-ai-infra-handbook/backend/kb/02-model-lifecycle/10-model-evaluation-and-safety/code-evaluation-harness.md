## 一句话结论

固定数据版本、模板、解码参数、随机种子和评分器，并输出逐样本证据与聚合区间。

## 原理与系统位置

- **核心对象**：手写可复现评测 Harness。
- **分析维度**：任务分类、评分、统计、人评、Judge、红队和回归门槛。
- **因果链**：先明确输入规模与状态，再写出计算、内存、通信或 I/O 路径，最后定位关键路径上的限制因素。

## 工程权衡

落地时必须同时核对正确性、质量、吞吐/延迟、资源成本与运维复杂度。单点峰值不能代表端到端收益；局部优化还可能把瓶颈推到队列、网络、存储或下游服务。

## 具体例子

做设计评审时，先列出 batch、序列长度、并发、数据精度和拓扑等输入，再估算资源账本；上线后以 准确率、pass@k、置信区间、一致性和攻击成功率 对照估算。若观测与模型不一致，应优先检查隐式同步、缓存命中、数据倾斜和测量口径。

## 观测与排障

先用端到端指标确认用户影响，再沿关键路径下钻。每次只改变一个变量，保留基线、版本和逐样本/逐请求证据，避免把相关性误判为因果。
