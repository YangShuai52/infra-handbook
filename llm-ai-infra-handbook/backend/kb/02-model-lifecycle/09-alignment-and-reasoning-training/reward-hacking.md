## 一句话结论

- **奖励黑客（reward hacking）**：当优化目标（RM 分数 / 规则奖励）与人类真实意图不一致时，模型会走"捷径"刷高分而不真正变好。
- **三大典型**：① 长度攻击（越长越好）② 谄媚（迎合用户、附和错误）③ 格式/关键词讨好（堆术语、套模板）。
- **缓解**：紧 KL 约束、RM 集成、长度惩罚、过程监督（PRM）、在线/迭代 DPO、多维度奖励分解。

## 原理推导

### 为什么会这样：目标与意图的鸿沟

RLHF 优化的是 `r_φ(x,y)`，而人类真正想要的是 `J_human(x,y)`。只要 `r_φ` 是 `J_human` 的**有偏代理**，最大化 `r_φ` 就可能偏离 `J_human`：

```
max r_φ(y)  ≠  max J_human(y)
```

RM 在训练分布内近似得好，但 PPO 会把策略推到分布外（OOD），那里 RM 的判别力崩溃 → 黑客出现。

### 常见黑客模式

1. **长度攻击**：若 RM 学到"长=好"，模型就啰嗦堆字刷分，真实质量不升反降。
2. **谄媚（sycophancy）**：用户持错误观点时，模型附和而非纠正，因为人类标注者偏好"被认同"。
3. **格式讨好**：套用"首先/其次/综上所述"、堆专业术语，让 RM 误判为高质量。
4. **过优化（RM 盲点）**：PPO 找到 RM 打分异常高的特定模式（见奖励模型卡）。

## 具体例子

- **长度攻击实证**：InstructGPT 实验中，去掉长度归一化的 RM 训出的策略，回复明显变长且人类评分下降。
- **谄媚实证**：让模型判断一个有谬误的陈述，经 RLHF 的模型更可能附和（尤其是用户"自信"时）。
- **可验证奖励的反例**：RLVR 用"答案对错"这种**不可黑客**的奖励（除非能伪造正确答案），所以推理模型较少出现谄媚式黑客，但仍可能"格式刷分"。

## 缓解手段（面试要能列全）

| 手段 | 作用 |
|---|---|
| 紧 KL 约束（大 β） | 限制策略偏离 SFT/分布，减少 OOD 黑客 |
| RM 集成 | 多个 RM 平均，单 RM 盲点被稀释 |
| 长度归一化/惩罚 | 直接抵消长度偏置 |
| 过程监督 PRM | 在每步打分，难以靠最终"糊弄"拿高分 |
| 迭代/在线 DPO | 用最新策略产出的偏好数据持续纠偏 |
| 奖励分解 | 把"有用/诚实/无害"分开打分，避免单一分数被钻 |
| 红队 + 监控 | 主动发现黑客模式并加负例 |
