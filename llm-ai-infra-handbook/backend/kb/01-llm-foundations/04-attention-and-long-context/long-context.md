## 一句话结论

四种方案的本质区别，用一句话概括：

```
ALiBi        : 不用位置编码，直接在 attention 分数上加一个与距离成正比的线性惩罚
PI（位置插值）: 把位置索引整体缩小，所有 RoPE 频率一起变密
NTK-aware    : 只改 base，等效于"高频几乎不动、低频被拉伸"
YaRN         : 按波长分段决定插值强度（低频多插、高频不插）+ attention 温度修正
```

**选型建议**：新训练的长上下文模型直接调大 base（LLaMA-3 用 500000）；已有短上下文模型要扩展，用 **YaRN + 少量长数据微调**（通常只需原始训练量的 0.1%~1%）；不想改结构也不想微调时用 NTK-aware（Dynamic NTK）作为推理时的兜底。

## 原理推导

### 1. ALiBi（Attention with Linear Biases）

ALiBi 完全去掉位置编码，改为在 attention 分数上加一个静态偏置：

```
score_{ij} = q_i·k_j / √d_h  -  m · |i - j|
```

其中 m 是每个头固定的斜率，按头数几何衰减：

```
m_h = 2^(-8h/H),  h = 1..H       （H=8 时: 2^-1, 2^-1.5, ..., 2^-8）
```

不同头用不同斜率 = 不同头关注不同距离尺度：斜率大的头只看近处，斜率小的头能看很远。

**优点**：
- 天然的"外推"能力：距离再大也只是加一个更大的负数，不会失效
- 零额外参数、零训练改动
- 训练短、推理长（train short, test long）效果显著优于 RoPE

**缺点**：
- 偏置是静态的、与内容无关，表达能力弱于 RoPE 的动态旋转
- 长上下文下显存/算力没有任何节省（仍是满 O(S²)）
- 与 FlashAttention 的融合需要处理偏置项
- 实践中最终效果不如调好 base 的 RoPE，所以现代主流模型（LLaMA-3、Qwen）都回归了 RoPE

### 2. PI（Position Interpolation）

把位置索引统一缩放，使长序列"挤进"训练长度：

```
原始:  θ_j · m
PI:    θ_j · (m / s),   s = L_target / L_train
```

例如 4k 训练 → 32k 目标，s = 8。位置 32000 被映射成 4000，正好落在训练区间末端。

**为什么有效**：RoPE 的相位 `m·θ_j` 是周期性的，只要把所有相位压缩到训练见过的范围内，模型就能处理。

**为什么不够好**：**所有频率被同等压缩**。高频维度（负责近距离分辨）本来在 4k 内已经跑了几十圈，压缩 8 倍后相邻位置的相位差变成 1/8，近距离位置变得难以区分，短上下文性能明显下降。

### 3. NTK-aware 插值

关键洞察：不要缩放位置索引，而是**缩放 base**，效果是高频维度和低频维度被区别对待。

设缩放因子 s，推导目标：让最高频（j=0，θ=1）几乎不变，最低频按 PI 的需求缩放。

NTK 的构造（记 d = d_h）：

```
base' = base · s^(d / (d - 2))
```

验证两条极端：

```
j = 0 (最高频, θ_0 = 1):
    θ'_0 = base'^(-0/d) = 1          → 完全不变 ✓

j = d/2 - 1 (最低频):
    θ' = base'^(-(d-2)/d) = (base · s^(d/(d-2)))^(-(d-2)/d)
       = base^(-(d-2)/d) · s^(-1)    → 恰好是 PI 的 1/s 缩放 ✓
```

中间维度则平滑过渡。这就是"NTK-aware"名字的由来——借用了神经切线核（NTK）理论中"高频分量外推难、低频分量外推易"的结论。

**对比 PI 的核心优势**：近处位置（高频维主导）分辨力完全保留，只把远处（低频维）拉伸，所以**几乎不需要微调**就能外推，短上下文性能也不掉。

**Dynamic NTK**：推理时按当前实际长度动态计算 s：

```
s = max(1, L_current / L_train)
```

这样短输入用原始 base（无损失），长输入自动插值。是很多推理框架（如 llama.cpp）的默认外推方式。

### 4. YaRN（Yet another RoPE extensioN）

YaRN 在 NTK-aware 基础上加了两件事。

**第一件：ramp 函数（按波长分段插值）**

先定义第 j 维在长度 L 下"跑完一圈"的程度（波长占比）：

```
r_j = L_train / T_j = L_train · θ_j / (2π)
```

- r_j 大 → 该维在训练长度内跑了多圈 → 高频 → **不该插值**（相位信息已充分学习）
- r_j 小 → 该维在训练长度内没跑完一圈 → 低频 → **可以插值**

设两个阈值 α=1, β=32，定义 ramp 函数：

```
γ(r) = 0                        if r < α        （高频：不插值，保持原样）
γ(r) = 1                        if r > β        （低频：完全按 PI 插值）
γ(r) = (r - α) / (β - α)        otherwise       （中间：线性过渡）
```

于是第 j 维的频率被修正为：

```
θ'_j = (1 - γ(r_j)) · θ_j  +  γ(r_j) · θ_j / s
```

即高频保持 θ_j，低频变成 θ_j/s，中间平滑过渡。这比 NTK-aware 的"几何插值"更显式、更可控。

**第二件：注意力温度修正**

YaRN 发现插值后 attention 分布的熵发生了变化，需要给 logits 乘一个温度：

```
softmax( q·k / (√d_h · t) ),     t ≈ 0.1 · ln(s) + 1
```

例如 s = 16 时，`t = 0.1 × ln(16) + 1 = 0.1 × 2.77 + 1 = 1.277`。

为什么是除以 t（t>1，即降低 logits 的锐度）：插值让所有位置"挤在一起"，相对距离在相位上变小了，注意力分布变得更平（熵更高），乘以 1/t 相当于进一步平滑以匹配原始分布的"有效距离感"——实践上这个修正确实显著降低 PPL。

### 5. 长上下文训练本身

除了位置编码，长上下文能力还需要：

1. **长数据**：把长文档拼接到目标长度做继续预训练（不是简单地把短文档 padding，要真实的跨段落依赖）
2. **渐进式长度**（课程学习）：4k → 8k → 32k → 128k 逐步扩展，比一步到位稳定
3. **数据配比的坑**：长文档（书籍、代码仓库）与短文档混合，不能全是长文档否则短上下文退化
4. **序列并行**：超长序列单卡放不下，需要 Ring Attention / Ulysses / DeepSpeed-Ulysses 沿序列维切分
5. **评测**：Needle-in-a-Haystack（大海捞针）只能测"检索"，不能测"推理"；更全面的用 RULER（含多跳检索、变量追踪、聚合等）

## 具体例子

**例 1：各方案的缩放因子计算（4k → 32k，s = 8，d_h = 128）**

```
PI:
  θ'_j = θ_j / 8，对所有 j
  位置 32000 → 等效位置 4000

NTK-aware:
  base' = 10000 × 8^(128/126) = 10000 × 8^1.0159
        = 10000 × 8.26 = 82,600
  θ'_0 = 1                                    （不变）
  θ'_63 = (82600)^(-126/128) = 82600^(-0.9844)
        = 10000^(-0.9844) × 8^(-1)            （正好是 PI 的 1/8）

YaRN (α=1, β=32):
  L_train = 4096
  j=0:  r_0 = 4096 × 1 / (2π) = 651.9 > 32 → γ=1 → 完全插值？
```

等一下，这里有个常见误解要澄清：**r_j 的大小与"高频/低频"的对应关系**。r_j 大表示该维在训练长度内跑了多圈，即**高频**。上面 j=0 时 r=652 > β=32，γ=1，会完全插值——这似乎与"高频不插值"矛盾。

正确的理解是：YaRN 论文中 ramp 的另一个等价表述是按**波长**判断。波长 `λ_j = 2π/θ_j`，若 `λ_j < L_train`（该维在训练长度内至少转了一圈）→ 已充分学习 → 不插值；若 `λ_j > L_train` → 未见过完整周期 → 插值。用 r 表示时，`r_j = L_train/λ_j`，所以 **r 大 = 波长短 = 高频 = 不插值**，即 `γ(r)` 应是 r 的**递减**函数。论文中给出的写法是：

```
γ_j = 0                         if r_j > β     （高频/短波长：不插值）
γ_j = 1                         if r_j < α     （低频/长波长：完全插值）
γ_j = (β - r_j) / (β - α)       otherwise
```

（不同实现的 α/β 取值和方向写法有出入，面试时说清楚"**短波长维保持原频率、长波长维做插值、中间线性过渡**"这个物理含义即可，不必死记公式方向。）

**例 2：Dynamic NTK 的实际计算**

训练长度 4096，当前推理长度 16384：

```
s = 16384 / 4096 = 4
base' = 10000 × 4^(128/126) = 10000 × 4.089 = 40,890
t     = 0.1 × ln(4) + 1 = 1.139
```

**例 3：外推能力的定量对比（典型实验结论）**

LLaMA-2-7B（4k 训练），在 32k 长度上的 PPL 表现（相对值，越小越好）：

```
直接外推（不做处理）    : PPL 爆炸（>100）
PI + 1000 步微调        : 接近训练长度水平
NTK-aware（零微调）      : 可用，PPL 略高
YaRN + 400 步微调       : 最优，且短上下文无退化
```

微调步数的量级差异很重要：**YaRN 通常只需几百到几千步、用原始预训练数据量的 0.1%，而 PI 需要更大量的长文本微调**。这是 YaRN 在工程上受欢迎的核心原因。

**例 4：base 与理论窗口**

```
base = 10000,  d_h = 128  →  最长波长 ≈ 5.1e4 tokens
base = 500000, d_h = 128  →  最长波长 ≈ 2.7e6 tokens   （LLaMA-3 支持 128k）
base = 1e6                →  ≈ 5.5e6 tokens
```

LLaMA-3 的做法是**先把 base 从 10000 提到 500000 再做 128k 的长上下文微调**，属于"改结构 + 微调"的组合拳，比纯粹的推理时插值更彻底。

## 代码速记

```python
import torch, math

def rope_freqs(dim, seq_len, base=10000.0, scale=1.0):
    inv = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim)) / scale
    t = torch.arange(seq_len, dtype=torch.float32)
    return torch.outer(t, inv)

# ---------- PI：统一缩放位置索引 ----------
def freqs_pi(dim, seq_len, base, s):
    t = torch.arange(seq_len, dtype=torch.float32) / s
    inv = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
    return torch.outer(t, inv)

# ---------- NTK-aware：缩放 base ----------
def freqs_ntk(dim, seq_len, base, s):
    base_new = base * s ** (dim / (dim - 2))
    return rope_freqs(dim, seq_len, base_new)

# ---------- Dynamic NTK ----------
def freqs_dynamic_ntk(dim, seq_len, base, train_len):
    s = max(1.0, seq_len / train_len)
    return freqs_ntk(dim, seq_len, base, s)

# ---------- YaRN ----------
def freqs_yarn(dim, seq_len, base, s, train_len, alpha=1, beta=32):
    inv = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
    wave_len = 2 * math.pi / inv                      # 每个维度的波长
    r = train_len / wave_len                          # 训练长度内转了几圈
    gamma = torch.zeros_like(r)
    gamma[r < alpha] = 1.0                            # 长波长(低频) → 完全插值
    gamma[r > beta] = 0.0                             # 短波长(高频) → 不插值
    mid = (r >= alpha) & (r <= beta)
    gamma[mid] = (beta - r[mid]) / (beta - alpha)     # 线性过渡
    inv_new = inv * (1 - gamma) + (inv / s) * gamma   # 分段插值
    t = torch.arange(seq_len, dtype=torch.float32)
    return torch.outer(t, inv_new)

def yarn_temperature(s):
    """YaRN 的 logits 温度修正"""
    return 0.1 * math.log(s) + 1.0

# s=16 时
print(f"t = {yarn_temperature(16):.3f}")   # 1.277
```

## 面试追问

**Q：为什么 RoPE 直接外推会失败，而 ALiBi 不会？**
A：RoPE 是"相位"编码，训练时只见过 `|m-n| < L_train` 范围内的相位差，超出后高频维度的相位进入了完全未见的区间（跑了太多圈，与训练时的相对关系不再对应），注意力分数分布失真。ALiBi 的偏置是线性的、无上界的单调惩罚，距离再大也只是"更负"，模型在训练时就理解了"更远 = 分数更低"这个规律，所以能自然外推。本质区别是**周期性编码 vs 单调惩罚**。

**Q：PI 和 NTK-aware 哪个需要微调？**
A：PI 必须微调（因为高频被压缩破坏了近距离分辨力，模型需要重新适应），通常需要数千步长文本训练。NTK-aware 可以零微调使用（高频不变，模型在近距离的行为完全没变），微调只是锦上添花。YaRN 介于两者之间——零微调可用，但配合极少量微调（几百步）效果最好。

**Q：为什么不能直接把训练长度拉到 128k 一步到位？**
A：三个问题。(1) 算力：attention 是 O(S²)，128k 的注意力成本是 4k 的 1024 倍，全部数据都按 128k 训练代价不可接受；(2) 数据：真正有长程依赖的长文档很稀缺，强行把短文档拼到 128k 会让模型学到大量"跨文档无关"的注意力模式；(3) 优化：长序列的梯度噪声更大、更容易不稳定。所以工业界都用渐进式 + 混合长度的 curriculum。

**Q：长上下文评测该怎么做？大海捞针够吗？**
A：不够。Needle-in-a-Haystack 只能验证"能不能从长文本里精确检索出一个事实"，这是长上下文能力里最基础的一层。实践中模型经常"能找到针但不会用针"（检索到了但推理时没用上）。更全面的方案是 RULER，它包含：多 value 检索、多 key 检索、变量追踪（variable assignment）、聚合（common/frequent words extraction）、以及带干扰项的多跳检索。另外一定要同时测**短上下文性能是否退化**——很多长上下文方案是拿短上下文性能换来的。

**Q：窗口注意力（Sliding Window）能不能做长上下文？**
A：能做"长输入"，但不能做"完全的长程依赖"。滑动窗口（如 Mistral 的 W=4096）把复杂度从 O(S²) 降到 O(S·W)，配合层间堆叠（第 l 层能看到 l·W 的范围）实现"感受野"随层数线性增长。这在绝大多数任务上够用，但对需要精确回忆超远距离细节的任务（如"第 3 章提到的那个人名"）无能为力。所以常见做法是**窗口层 + 少量全局层交替**，或者窗口 + 长上下文微调的组合。

**Q：长上下文和 RAG 是什么关系，能互相替代吗？**
A：不能完全替代，是互补。长上下文的优势是"全局视野"（能跨文档推理、能理解结构），RAG 的优势是"成本低、可更新、可溯源"。定量上：128k 上下文每请求成本是 4k 的几十倍，而 RAG 只检索 top-5 段落成本几乎不变；但 RAG 受限于召回质量，召回不到就完全无法回答，而长上下文不会漏。实践结论：**8k~32k 以内用长上下文，超大规模知识库用 RAG，两者可以结合（长上下文 + 检索到的段落）**。
